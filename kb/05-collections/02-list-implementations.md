`ArrayList` против `LinkedList` — классический вопрос, на котором кандидаты
повторяют таблицу сложностей из учебника: «вставка в `LinkedList` — O(1)». На
senior-уровне ждут большего: как растёт массив `ArrayList`, почему вставка в
середину `LinkedList` на практике медленнее, чем в `ArrayList`, и почему
`Vector` и `Stack` не используют в новом коде.

## Ключевые концепции

### ArrayList

#### Динамический массив Object[]
`ArrayList` хранит элементы во внутреннем массиве `Object[] elementData` и
счётчик `size`. Важно различать размер и ёмкость (capacity): `size` — сколько
элементов в списке, ёмкость — длина массива, то есть сколько поместится без
перевыделения. Свободный хвост массива заполнен `null`.

`new ArrayList<>()` не создаёт массив на 10 элементов сразу: до первого `add`
список ссылается на общий пустой массив, и только первое добавление выделяет
массив ёмкостью 10. Так пустые списки, которых в приложении много, не тратят
память. Конструктор `new ArrayList<>(n)` сразу выделяет массив нужной длины.

#### resize: рост в 1,5 раза
Когда массив заполнен, `add` создаёт новый массив большей длины и копирует в
него элементы через `Arrays.copyOf` (внутри — `System.arraycopy`). Новая ёмкость
— старая плюс её половина: `old + (old >> 1)`. Старый массив становится мусором.

Рост в 1,5 раза — компромисс между числом копирований и перерасходом памяти.
Если итоговый размер известен заранее, ёмкость задают в конструкторе или через
`ensureCapacity`. Лишний хвост после заполнения можно отрезать `trimToSize()`.

Рост ёмкости по шагам (внутреннее поле прочитано рефлексией, запуск с
`--add-opens java.base/java.util=ALL-UNNAMED`):
```java
static int capacity(ArrayList<?> list) throws Exception {
    Field f = ArrayList.class.getDeclaredField("elementData");
    f.setAccessible(true);
    return ((Object[]) f.get(list)).length;
}
// ...
ArrayList<Integer> list = new ArrayList<>();
System.out.println("new ArrayList<>(): size=0, capacity=" + capacity(list));
// add 50 элементов, печатаем каждое изменение ёмкости
list.trimToSize();
```
```
new ArrayList<>(): size=0, capacity=0
add #1: capacity 0 -> 10
add #11: capacity 10 -> 15
add #16: capacity 15 -> 22
add #23: capacity 22 -> 33
add #34: capacity 33 -> 49
add #50: capacity 49 -> 73
trimToSize(): size=50, capacity=50
```
Пустой список вообще без массива, первое добавление выделило 10 ячеек, дальше
каждый рост — примерно в 1,5 раза. На 50 элементов пришлось шесть
перевыделений; с `new ArrayList<>(50)` не было бы ни одного.

#### Сложность операций
`get(index)` и `set(index, e)` — O(1): адрес элемента вычисляется по индексу.
`add(e)` в конец — амортизированное O(1): почти всегда это запись в свободную
ячейку, а редкие копирования при росте «размазываются» по всем добавлениям.
Суммарная стоимость n добавлений — O(n).

Вставка и удаление в начале или середине — O(n): все элементы правее сдвигаются
через `System.arraycopy`. При этом сдвиг — одно быстрое блочное копирование
памяти, а не цикл в байткоде. `contains` и `indexOf` — линейный поиск, O(n).

### LinkedList

#### Двусвязный список узлов
`LinkedList` хранит каждый элемент в отдельном объекте-узле `Node` с тремя
полями: `prev`, `item` и `next`. Сам список держит ссылки на первый и последний
узлы и `size`. Массива нет, перевыделений тоже нет: каждое добавление создаёт
один новый узел.

Цена — память и локальность. Узел — отдельный объект с заголовком: около 24 байт
при compressed oops, плюс сам элемент. Узлы разбросаны по куче, поэтому обход
списка постоянно промахивается мимо кэша процессора. Замер в теме «Выбор
правильной коллекции» показывает: на миллион `Integer` `LinkedList` занимает
вдвое больше памяти, чем `ArrayList`.

#### Операции на концах O(1), доступ по индексу O(n)
Добавление и удаление на концах — O(1): достаточно перевесить пару ссылок.
Доступ по индексу — O(n): `get(i)` идёт по цепочке узлов от ближайшего конца,
поэтому худший случай — середина списка. Цикл `for (int i...) list.get(i)` по
`LinkedList` превращается в O(n²).

Распространённое заблуждение — «вставка в середину `LinkedList` за O(1)».
Перевесить ссылки действительно дёшево, но сначала до нужной позиции надо
дойти, а это O(n). Дешёвой вставка бывает только через `ListIterator`, который
уже стоит на нужном месте.

Сравнение на 100 000 элементов (второй проход после прогрева):
```java
List<Integer> al = new ArrayList<>(), ll = new LinkedList<>();
// add в конец: al.add(i) / ll.add(i)
// add в начало: list.add(0, i)
// get по индексу: ArrayList — 100 000 вызовов, LinkedList — только 10 000
// add в середину: list.add(list.size() / 2, i), 10 000 раз
```
```
add в конец, 100000 шт.:      ArrayList    1 ms | LinkedList    4 ms
add(0, x), 100000 шт.:        ArrayList  305 ms | LinkedList    0 ms
get(i): ArrayList 100000 раз    1 ms | LinkedList 10000 раз  423 ms
add в середину, 10000 шт.: ArrayList   31 ms | LinkedList  693 ms
```
`LinkedList` выиграл только вставку в начало — там `ArrayList` сдвигает весь
массив. В середину `ArrayList` вставил в 20 раз быстрее: блочный сдвиг
половины массива дешевле, чем пройти половину списка по ссылкам. А
`get(i)` по `LinkedList` даже на десятикратно меньшем числе вызовов оказался
на порядки медленнее.

#### List и Deque одновременно
`LinkedList` реализует не только `List`, но и `Deque`: у него есть `addFirst`,
`pollLast`, `push`, `pop` и другие операции двусторонней очереди. Исторически
его часто использовали как очередь. Сегодня для этого есть `ArrayDeque`,
который быстрее (тема «Queue и Deque»), а у `LinkedList` остаётся редкая ниша:
частые вставки и удаления через итератор и элементы `null`, которые
`ArrayDeque` не принимает.

```java
LinkedList<String> ll = new LinkedList<>(List.of("b", "c"));
ll.addFirst("a");
ll.addLast("d");
System.out.println(ll + ", pollFirst=" + ll.pollFirst() + ", pollLast=" + ll.pollLast() + ", осталось " + ll);
```
```
[a, b, c, d], pollFirst=a, pollLast=d, осталось [b, c]
```
Один и тот же объект работает и как список, и как двусторонняя очередь.

### Устаревшие варианты

#### Vector и Stack
`Vector` — список на массиве из Java 1.0, у которого почти все методы
`synchronized`. Растёт он вдвое, а не в 1,5 раза. Синхронизация на каждом
вызове не делает составные операции потокобезопасными: «проверить и добавить»
из двух вызовов всё равно требует внешней блокировки, а в однопоточном коде
блокировки — лишние накладные расходы.

`Stack` наследует `Vector` и поэтому разрешает вставку в любое место, что
ломает семантику стека (тема «Композиция vs наследование»). Замены:
`ArrayList` для списка, `ArrayDeque` для стека и очереди,
`CopyOnWriteArrayList` или `Collections.synchronizedList` для разделяемого между
потоками списка.

```java
Vector<Integer> v = new Vector<>();
// add 41 элемент, печатаем каждое изменение ёмкости
```
```
new Vector<>(): capacity=10
add #11: capacity 10 -> 20
add #21: capacity 20 -> 40
add #41: capacity 40 -> 80
```
В отличие от `ArrayList`, массив создаётся сразу и удваивается при каждом росте.

## Частые вопросы на собеседовании

**Q: Как устроен ArrayList и как он растёт?**
A: Внутри массив `Object[]` и счётчик `size`. Массив выделяется лениво — ёмкость
10 при первом `add`. При заполнении создаётся массив в 1,5 раза больше
(`old + (old >> 1)`), и элементы копируются через `System.arraycopy`. Поэтому
добавление в конец — амортизированное O(1), а если размер известен заранее,
ёмкость лучше задать в конструкторе.

**Q: Когда LinkedList быстрее ArrayList?**
A: Почти никогда. Он выигрывает при вставке и удалении в начале списка и при
изменениях через `ListIterator`, уже стоящий на нужной позиции. Вставка в
середину по индексу медленнее, чем у `ArrayList`, потому что до позиции надо
дойти по ссылкам. Плюс `LinkedList` тратит вдвое больше памяти и плохо
использует кэш процессора.

**Q: Почему add в конец ArrayList — амортизированное O(1), а не O(1)?**
A: Иногда добавление вызывает перевыделение массива с копированием всех
элементов — это O(n). Но ёмкость растёт геометрически, поэтому копирования
редки, и суммарная стоимость n добавлений — O(n). В среднем на одно добавление
приходится O(1), хотя отдельный вызов может быть дорогим.

**Q: Почему Vector и Stack считаются устаревшими?**
A: `Vector` синхронизирует каждый метод, что лишнее в однопоточном коде и
недостаточно для составных операций в многопоточном. `Stack` наследует
`Vector` и позволяет вставлять элементы в середину стека. Им на смену пришли
`ArrayList`, `ArrayDeque`, concurrent-коллекции и обёртки
`Collections.synchronizedList`.

## Ловушки и частые ошибки

#### get(i) в цикле по LinkedList
Цикл `for (int i = 0; i < list.size(); i++) list.get(i)` по `LinkedList` — O(n²):
каждый `get` проходит список от края. Код, написанный для `List` и протестированный
на `ArrayList`, внезапно тормозит, когда ему передают `LinkedList`. Для обхода
используют for-each или итератор, а общий код может проверить маркер
`RandomAccess`.

#### Список без начальной ёмкости
Сборка большого списка известного размера через `new ArrayList<>()` делает
десятки перевыделений и копирований. При пакетной обработке и маппинге
результатов из базы ёмкость задают сразу: `new ArrayList<>(rows.size())`.

#### Утечка памяти через subList
`subList` возвращает представление, которое держит ссылку на весь исходный
список. Если сохранить маленький `subList` от огромного списка, огромный список
не будет собран. Для долгоживущего фрагмента делают копию:
`new ArrayList<>(list.subList(0, 10))`.

#### synchronized-методы — не потокобезопасность
`Vector` и `Collections.synchronizedList` синхронизируют отдельные вызовы, но не
их последовательности. `if (!list.contains(x)) list.add(x)` в двух потоках
добавит дубликат, а обход без внешнего `synchronized` может упасть с
`ConcurrentModificationException`.
