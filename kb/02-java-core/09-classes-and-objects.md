Базовый синтаксис ООП в Java — то, с чего формально начинается язык. Но здесь
закладываются детали, которые потом всплывают в более сложных темах: что
происходит при `new`, почему конструктор по умолчанию существует не всегда,
чем статическая фабрика лучше конструктора и как устроены модификаторы
доступа.

## Ключевые концепции

### Создание объекта

#### Что происходит при new
Выражение `new Point(1, 2)` выполняется в несколько шагов. Сначала JVM
загружает и инициализирует класс, если это ещё не сделано. Затем выделяет
память под объект в куче и заполняет все поля значениями по умолчанию: нулями,
`false` и `null`.

После этого вызывается конструктор: он по цепочке `super(...)` доходит до
`Object`, затем на каждом уровне выполняются инициализаторы полей и
instance-блоки и тело конструктора. Только после этого выражение `new`
возвращает ссылку на готовый объект. Подробный порядок с наследованием — в
теме «Порядок инициализации при наследовании».

#### Конструктор по умолчанию
Если в классе нет ни одного явного конструктора, компилятор генерирует
конструктор без параметров с той же видимостью, что у класса, — он только
вызывает `super()`. Как только объявлен хотя бы один конструктор, с
параметрами или без, конструктор по умолчанию больше не создаётся.

Отсюда частая ситуация: класс с единственным конструктором с параметрами
больше нельзя создать через `new SomeClass()`. Это важно и для фреймворков:
JPA и многие библиотеки сериализации требуют конструктор без параметров.

#### this(...) и super(...)
Конструктор может вызвать другой конструктор того же класса через `this(...)`.
Так общую логику держат в одном «основном» конструкторе, а остальные делают
тонкими обёртками со значениями по умолчанию. `super(...)` вызывает
конструктор родителя; если его не написать, компилятор вставит `super()` сам.

До Java 24 включительно правило было жёстким: `this(...)` или `super(...)`
обязаны быть первой инструкцией конструктора. Даже проверку аргумента нельзя
было сделать до вызова родителя — её выносили в статический метод внутри
аргументов `super(...)`.

В Java 25 правило ослаблено (JEP 513, Flexible Constructor Bodies): перед
вызовом разрешён пролог. В нём нельзя обращаться к создаваемому объекту —
читать поля, вызывать методы, передавать `this`, — но можно проверять и
готовить аргументы и присваивать поля своего класса без инициализатора.

#### Ключевое слово this
`this` внутри метода или конструктора — ссылка на текущий объект. Чаще всего
она нужна, когда параметр называется так же, как поле, и затеняет его
(shadowing): в `this.value = value` слева поле, справа параметр.

Без `this.` присваивание `value = value` присвоит параметр самому себе, а поле
останется нулевым — компилятор при этом не жалуется. `this` также передают
как аргумент, когда объект регистрирует себя где-то (слушатель, callback), и
возвращают из методов fluent-API.

#### Порядок инициализации внутри класса
В пределах одного класса без наследования порядок фиксирован. Один раз при
первой инициализации класса выполняются static-блоки и static-инициализаторы
полей в порядке их объявления в тексте. При каждом создании объекта
выполняются инициализаторы полей и instance-блоки в порядке объявления, и
только потом тело конструктора.

Порядок объявления имеет значение: поле, инициализированное через другое поле,
объявленное ниже, увидит его ещё в значении по умолчанию.

### Статические фабрики и приватные конструкторы

#### Статический фабричный метод
Вместо конструктора класс может предоставить статический метод, возвращающий
экземпляр: `Integer.valueOf`, `List.of`, `LocalDate.of`,
`Optional.empty`. Effective Java (Item 1) рекомендует рассматривать такой
вариант в первую очередь.

У фабрики есть имя, которое объясняет смысл (`Money.ofRubles` и
`Money.ofCents` вместо двух конструкторов с одинаковыми параметрами). Она не
обязана создавать новый объект — может вернуть закэшированный, как
`Integer.valueOf`. И она может вернуть подтип или скрытую реализацию: `List.of`
возвращает внутренний неизменяемый класс, который не виден снаружи.

Минусы — фабрику труднее найти в документации, чем конструктор, а класс без
публичного или защищённого конструктора нельзя унаследовать. Обычно это
скорее плюс: наследованию предпочитают композицию.

#### Приватный конструктор
Конструктор можно сделать `private`, чтобы запретить создание объектов
снаружи. Так поступают с классами-утилитами со статическими методами
(`Collections`, `Math`) — там приватный конструктор часто бросает
`AssertionError`, чтобы его не вызвали и рефлексией. Так же устроены
статические фабрики и singleton.

### Модификаторы и структура

#### Четыре уровня видимости
У членов класса четыре уровня видимости. `private` — только внутри класса
(включая вложенные классы). Package-private — без модификатора, виден внутри
пакета. `protected` — пакет плюс подклассы в других пакетах. `public` — везде,
где виден сам класс.

Особенность Java — `protected` открывает доступ и всему пакету, а не только
наследникам, как в некоторых других языках. А у package-private нет ключевого
слова: отсюда путаница новичков, которые ищут модификатор `default`. Классы
верхнего уровня бывают только `public` или package-private.

#### Пакеты и правило одного public-класса на файл
Пакет — пространство имён и единица видимости: от него зависят
package-private и частично `protected`. Пакет соответствует директории, а
именование через обратный домен (`com.example.project`) — соглашение для
уникальности, а не требование языка.

Компилятор требует, чтобы в `.java`-файле был не больше чем один `public`-класс
верхнего уровня, и чтобы имя файла совпадало с его именем с учётом регистра.
Не-`public` классов в одном файле может быть сколько угодно, но на практике
каждый класс держат в своём файле.

## Примеры

Порядок инициализации и вызов `this(...)`:
```java
public class Obj {
    static { System.out.println("1. static-блок Obj"); }
    static int counter = initCounter();
    static int initCounter() { System.out.println("2. static-инициализатор поля counter"); return 0; }

    { System.out.println("3. instance-блок Obj"); }
    int id = initId();
    int initId() { System.out.println("4. instance-инициализатор поля id"); return 0; }

    Obj() {
        this(42);
        System.out.println("6. тело конструктора Obj()");
    }
    Obj(int x) {
        System.out.println("5. тело конструктора Obj(int) — вызван через this(42)");
    }

    public static void main(String[] args) {
        System.out.println("--- создаём первый объект ---");
        new Obj();
        System.out.println("--- создаём второй объект (static уже не повторится) ---");
        new Obj();
    }
}
```
```
1. static-блок Obj
2. static-инициализатор поля counter
--- создаём первый объект ---
3. instance-блок Obj
4. instance-инициализатор поля id
5. тело конструктора Obj(int) — вызван через this(42)
6. тело конструктора Obj()
--- создаём второй объект (static уже не повторится) ---
3. instance-блок Obj
4. instance-инициализатор поля id
5. тело конструктора Obj(int) — вызван через this(42)
6. тело конструктора Obj()
```
Static-часть выполнилась один раз, ещё до первого `new`. Instance-часть
выполняется при каждом создании объекта, и тело `Obj()` идёт после тела
`Obj(int)`, потому что первым делом управление ушло в `this(42)`.

Статическая фабрика и затенение поля:
```java
static final class Money {
    private static final Money ZERO = new Money(0);
    private final long cents;

    private Money(long cents) { this.cents = cents; }

    static Money ofCents(long cents) { return cents == 0 ? ZERO : new Money(cents); }
    static Money ofRubles(long rubles) { return ofCents(Math.multiplyExact(rubles, 100)); }

    @Override public String toString() { return cents / 100 + "." + String.format("%02d", cents % 100) + " руб."; }
}

private int value = 1;
void shadow(int value) {
    System.out.println("параметр value = " + value + ", поле this.value = " + this.value);
}
// main:
System.out.println("Money.ofRubles(15) = " + Money.ofRubles(15));
System.out.println("ofCents(0) == ofCents(0): " + (Money.ofCents(0) == Money.ofCents(0)));
new Factory().shadow(42);
```
```
Money.ofRubles(15) = 15.00 руб.
ofCents(0) == ofCents(0): true
параметр value = 42, поле this.value = 1
```
Две фабрики с понятными именами принимают одинаковый тип параметра, что
невозможно для двух конструкторов. Нулевая сумма возвращается из кэша, а не
создаётся заново.

Имя файла не совпадает с public-классом:
```java
// файл WrongName.java
public class Foo { }
```
```
WrongName.java:1: error: class Foo is public, should be declared in a file named Foo.java
public class Foo { }
       ^
1 error
```

Конструктора по умолчанию нет:
```java
public class NoDefault {
    NoDefault(int x) {}
    public static void main(String[] args) {
        NoDefault n = new NoDefault(); // конструктора без параметров нет
    }
}
```
```
NoDefault.java:4: error: constructor NoDefault in class NoDefault cannot be
    applied to given types;
        NoDefault n = new NoDefault();
                      ^
  required: int
  found:    no arguments
  reason: actual and formal argument lists differ in length
1 error
```
Явный конструктор `NoDefault(int x)` отключил генерацию конструктора без
параметров.

## Частые вопросы на собеседовании

**Q: Когда генерируется конструктор по умолчанию и когда — нет?**
A: Только когда в классе нет ни одного явного конструктора. Как только объявлен
любой конструктор, генерация отключается, и конструктор без параметров нужно
писать самому, если он нужен — например, для JPA или десериализации.

**Q: Чем статический фабричный метод лучше конструктора?**
A: У фабрики есть говорящее имя, она может вернуть закэшированный объект вместо
нового и может вернуть подтип или скрытую реализацию. Минусы — её сложнее
найти в документации, и класс без доступного конструктора нельзя
унаследовать. Примеры в JDK: `Integer.valueOf`, `List.of`, `LocalDate.of`.

**Q: Чем protected в Java отличается от protected в C++?**
A: В Java `protected` даёт доступ и подклассам в любом пакете, и всем классам
своего пакета, даже не связанным наследованием. Это «package-private плюс
подклассы», а не ограничение только иерархией.

**Q: Почему this() и super() обязаны быть первой строкой конструктора?**
A: Правило не даёт коду конструктора обратиться к объекту до того, как
отработала инициализация родителя или альтернативного конструктора. До Java 24
это обеспечивалось требованием «первой строки». В Java 25 (JEP 513) перед
вызовом разрешён пролог: в нём можно проверять аргументы и присваивать поля
своего класса без инициализатора, но нельзя читать поля, вызывать методы и
передавать `this`.

## Ловушки и частые ошибки

#### «Конструктор по умолчанию есть всегда»
Добавление в существующий класс конструктора с параметрами молча убирает
конструктор по умолчанию. Код, создающий объекты без аргументов, и фреймворки,
которым он нужен, ломаются — на этапе компиляции или, хуже, в рантайме через
рефлексию.

#### Присваивание параметра самому себе
`value = value` в конструкторе или сеттере, где параметр затеняет поле,
компилируется без ошибок и оставляет поле пустым. Помогает привычка писать
`this.value` и предупреждения IDE о присваивании переменной самой себе.

#### package-private — не «доступ не ограничен»
Отсутствие модификатора — не «открыто для всех», а полноценный уровень
видимости в пределах пакета. Именно его часто выбирают для внутренних классов
модуля, которые не должны быть частью публичного API.

#### Инициализаторы полей и instance-блоки
Инициализатор поля (`int x = compute();`) и instance-блок (`{ ... }`) по
порядку исполнения равноправны: компилятор склеивает их в одну
последовательность в порядке объявления. Перестановка полей в классе может
изменить поведение, если один инициализатор зависит от другого.
