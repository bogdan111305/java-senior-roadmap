Базовый синтаксис, который кажется слишком простым для senior-собеседования, но
именно здесь проверяют внимательность. Классика жанра — `i = i++`, разница
между `&&` и `&`, `>>>` на отрицательных числах, распаковка `null` в тернарном
операторе и то, чем switch expression отличается от классического `switch`.

## Ключевые концепции

### Операторы

#### Порядок вычисления и инкремент
Java вычисляет операнды строго слева направо, а приоритет операторов
определяет только группировку. Постфиксный инкремент `i++` возвращает старое
значение и потом увеличивает переменную, префиксный `++i` — сначала
увеличивает, потом возвращает.

Отсюда известная головоломка `i = i++`. Правая часть запоминает старое
значение `i`, затем `i` увеличивается, а потом присваивание записывает в `i`
запомненное старое значение — инкремент теряется. Выражения, где одна
переменная меняется больше одного раза, пишут только в задачах на
собеседовании, но не в рабочем коде.

```java
int i = 0;
i = i++;
System.out.println("i = i++ -> " + i);
int j = 5;
int k = j++ + ++j;
System.out.println("j++ + ++j при j = 5 -> " + k + ", j = " + j);
```
```
i = i++ -> 0
j++ + ++j при j = 5 -> 12, j = 7
```
`j++ + ++j` равно 5 + 7: левый операнд вернул 5 и увеличил `j` до 6, правый
увеличил до 7 и вернул 7. Строгий порядок слева направо делает результат
детерминированным, но читать такой код всё равно тяжело.

#### Деление и остаток
Целочисленное деление отбрасывает дробную часть в сторону нуля: `-7 / 2` равно
`-3`, а не `-4`. Знак остатка `%` совпадает со знаком делимого, поэтому `-7 %
3` равно `-1`.

Это ломает наивные проверки вроде `x % 2 == 1` для нечётности — для
отрицательных `x` она ложна. Для «математического» остатка, всегда
неотрицательного при положительном делителе, есть `Math.floorMod`, а для
деления с округлением вниз — `Math.floorDiv`.

```java
System.out.println("-7 % 3 = " + (-7 % 3) + ", Math.floorMod(-7, 3) = " + Math.floorMod(-7, 3) + ", -7 / 2 = " + (-7 / 2));
```
```
-7 % 3 = -1, Math.floorMod(-7, 3) = 2, -7 / 2 = -3
```
`%` сохранил знак делимого, `floorMod` дал неотрицательный остаток, а деление
округлило `-3.5` к нулю.

#### Конкатенация строк и ассоциативность
Оператор `+` левоассоциативен, и как только один из операндов — строка,
дальше идёт конкатенация. Поэтому `"" + 1 + 2` даёт `"12"`, а `1 + 2 + ""` —
`"3"`: во втором случае сначала сложились два числа. Похожая ошибка — `"сумма:
" + a + b` вместо `"сумма: " + (a + b)`.

```java
System.out.println("\"\" + 1 + 2 = " + ("" + 1 + 2) + ", 1 + 2 + \"\" = " + (1 + 2 + ""));
```
```
"" + 1 + 2 = 12, 1 + 2 + "" = 3
```
Вычисление идёт слева направо: в первом случае строка встретилась раньше чисел,
во втором — позже.

#### Логические операторы: && / || vs & / |
У логических операторов `&&` и `||` есть аналоги `&` и `|`, которые тоже
работают с `boolean`. Логический результат у них одинаковый, а различие в том,
вычисляется ли правый операнд всегда.

`&&` и `||` — операторы с коротким замыканием (short-circuit): если левый
операнд `&&` уже `false` или левый операнд `||` уже `true`, правый не
вычисляется. `&` и `|` всегда вычисляют оба. На этом держится безопасность
`if (obj != null && obj.isValid())`: при `&` правая часть вызовется на `null` и
упадёт с `NullPointerException`.

```java
static boolean sideEffect(String label, boolean value) {
    System.out.println("  вычислили " + label);
    return value;
}
// ...
boolean r1 = false && sideEffect("B", true);
System.out.println("result=" + r1);
boolean r2 = false & sideEffect("B", true);
System.out.println("result=" + r2);
```
```
false && sideEffect:
result=false
false & sideEffect:
  вычислили B
result=false
```
При `&&` правый операнд не вычислялся вовсе, при `&` — вычислился, хотя
результат был известен заранее.

#### Битовые операторы и сдвиги
На целых числах `&`, `|`, `^`, `~` работают побитово: AND даёт 1, где оба бита
единицы, OR — где хотя бы один, XOR — где ровно один. `~x` инвертирует все
биты, что в дополнительном коде равно `-x - 1`.

`<<` сдвигает влево, заполняя младшие биты нулями (умножение на степень
двойки, пока нет переполнения). `>>` — арифметический сдвиг вправо: он
копирует знаковый бит, поэтому отрицательное число остаётся отрицательным.
`>>>` — логический сдвиг: старшие биты всегда заполняются нулями, и
отрицательное число превращается в большое положительное.

Неочевидная деталь — дистанция сдвига берётся по маске: для `int` учитываются
только младшие 5 бит, для `long` — 6. Поэтому `1 << 32` равно 1, а не 0, и
`1 << 33` равно 2. Битовые операции встречаются в реальном коде: `HashMap`
вычисляет индекс корзины как `(n - 1) & hash`, а флаги хранят в битовых масках.

```java
int a = 6, b = 3; // 0110, 0011
System.out.println("6 & 3 = " + (a & b));
System.out.println("6 | 3 = " + (a | b));
System.out.println("6 ^ 3 = " + (a ^ b));
System.out.println("~6 = " + (~a));
System.out.println("6 << 2 = " + (a << 2));
System.out.println("-8 >> 1 = " + (-8 >> 1));
System.out.println("-8 >>> 1 = " + (-8 >>> 1));
System.out.println("1 << 32 = " + (1 << 32) + ", 1 << 33 = " + (1 << 33) + ", 1L << 32 = " + (1L << 32));
```
```
6 & 3 = 2
6 | 3 = 7
6 ^ 3 = 5
~6 = -7
6 << 2 = 24
-8 >> 1 = -4
-8 >>> 1 = 2147483644
1 << 32 = 1, 1 << 33 = 2, 1L << 32 = 4294967296
```
`-8 >> 1` сохранил знак, а `-8 >>> 1` заполнил старший бит нулём и дал большое
положительное число. Сдвиг `int` на 32 — это сдвиг на 0, потому что
учитываются только 5 младших битов дистанции; у `long` маска шире, и сдвиг
работает.

#### Тернарный оператор
`condition ? a : b` — единственный оператор с тремя операндами, и он всегда
выражение: его можно использовать в присваивании, аргументе или `return`. Для
коротких случаев вроде `int max = a > b ? a : b;` это удобно, но вложенные
тернарные операторы читаются плохо — там понятнее `if/else` или switch
expression.

У тернарного оператора свои правила типа результата. Если одна ветка —
примитив, а другая — его обёртка, результат имеет тип примитива, и обёртка
распаковывается. Поэтому `Integer r = cond ? nullInteger : 0;` бросает
`NullPointerException`. А `true ? Integer.valueOf(1) : Double.valueOf(2)`
возвращает `1.0`: обе ветки приводятся к общему числовому типу `double`.

Обычное использование — выбрать одно из двух значений прямо в выражении:
```java
int a = 7, b = 12;
int max = a > b ? a : b;
System.out.println("max=" + max);
String status = (a % 2 == 0) ? "чётное" : "нечётное";
System.out.println("a=" + a + " -> " + status);
```
```
max=12
a=7 -> нечётное
```
Тернарный оператор вернул значение, которое сразу ушло в переменную, — с
`if/else` для этого понадобились бы две ветки с присваиванием.

Ловушки с типом результата:
```java
Integer nothing = null;
boolean cond = true;
Integer r = cond ? nothing : 0;   // тип выражения — int, nothing распаковывается
Object mixed = true ? Integer.valueOf(1) : Double.valueOf(2);
```
```
cond ? nullInteger : 0 -> NullPointerException
true ? Integer(1) : Double(2) -> 1.0
```
Обе ловушки — следствие правил типа результата: распаковка до `int` и
продвижение до `double`.

### Ветвление и циклы

#### if/else и классический switch
`if/else` — инструкция, а не выражение: значение она не возвращает. Классический
`switch` тоже инструкция, выбирающая ветку по значению. Он принимает `byte`,
`short`, `char`, `int` и их обёртки, `String` и `enum`, а с Java 21 — любой
ссылочный тип через pattern matching (раздел 10).

Главная опасность классического `switch` — проваливание (fall-through): без
`break` исполнение продолжается в следующей ветке независимо от её условия. Это
поведение унаследовано от C и сегодня чаще считается источником багов, чем
полезной возможностью.

`switch` по `String` компилируется в выбор по `hashCode()` с последующей
проверкой `equals`. А передача в любой `switch` значения `null` бросает
`NullPointerException` — если только среди веток нет `case null`, который
появился в Java 21.

Проваливание на практике:
```java
int day = 5;
switch (day) {
    case 4:
    case 5:
        System.out.println("почти выходные");
        // нет break — проваливаемся дальше
    case 6:
        System.out.println("выходной");
        break;
    default:
        System.out.println("будний день");
}
```
```
почти выходные
выходной
```
Ветка `case 6` выполнилась для `day = 5`, хотя её условие ложно: без `break`
исполнение просто перешло к следующим строкам. Пустой `case 4:` над `case 5:`
— то же проваливание, но намеренное: так объединяли значения до появления
`case 4, 5`.

`switch` и `null`:
```java
String s = null;
switch (s) { case "a": break; default: break; }   // классический switch
String res = switch (s) {
    case null -> "ветка case null";
    case "a" -> "a";
    default -> "другое";
};
```
```
switch (null) -> NullPointerException
switch с case null (Java 21) -> ветка case null
```
`switch` без `case null` на `null` падает — даже при наличии `default`. С
`case null` выбирается эта ветка.

#### Switch expression (Java 14+)
Switch expression со стрелками `->` решает проблему проваливания на уровне
языка: каждая ветка исполняет одно выражение или блок, `break` не нужен. Одна
ветка может объединять несколько значений: `case 1, 7 ->`.

Главное отличие — это выражение, возвращающее значение, поэтому его можно
присвоить или вернуть. Компилятор проверяет исчерпываемость: для `enum` и
sealed-иерархий можно обойтись без `default`, если обработаны все варианты, а
для `int` или `String` `default` обязателен. Внутри блочной ветки значение
возвращают через `yield`.

Стрелки и «выражение» — независимые свойства. Стрелочный синтаксис можно
использовать и в обычном switch-операторе без возвращаемого значения — там он
тоже убирает проваливание. А switch expression можно записать со старыми
двоеточиями и `yield`.

```java
int day = 3;
String kind = switch (day) {
    case 1, 7 -> "выходной";
    case 2, 3, 4, 5, 6 -> "будний";
    default -> "неизвестно";
};
System.out.println("day=" + day + " -> " + kind);

int other = 6;
switch (other) {
    case 6, 7 -> System.out.println("стрелочная форма в обычном switch: выходной");
    default -> System.out.println("будни");
}
```
```
day=3 -> будний
стрелочная форма в обычном switch: выходной
```
Первый `switch` вернул значение в переменную, второй — обычная инструкция, но
со стрелками: ни там, ни там проваливания нет.

#### for, while, do-while и for-each
`for` удобен, когда нужен счётчик или заранее известно число итераций. `while`
проверяет условие до тела и может не выполниться ни разу, `do-while` — после
тела и выполняется минимум один раз.

For-each (`for (Type x : source)`) — синтаксический сахар: для объекта,
реализующего `Iterable`, компилятор вызывает `iterator()` и в цикле
`hasNext()`/`next()`. Массивы `Iterable` не реализуют, но for-each для них
разрешён: компилятор превращает его в обычный цикл по индексу от `0` до
`length`.

```java
int n = 8;
while (n > 1) {
    System.out.println("while n=" + n);
    n /= 2;
}
int attempts = 0, limit = 0;
do {
    attempts++;
    System.out.println("do-while: попытка " + attempts);
} while (attempts < limit);
for (String name : List.of("Аня", "Борис")) {
    System.out.println("for-each: " + name);
}
for (int s : new int[] {90, 75}) System.out.println("for-each по массиву: " + s);
```
```
while n=8
while n=4
while n=2
do-while: попытка 1
for-each: Аня
for-each: Борис
for-each по массиву: 90
for-each по массиву: 75
```
`while` остановился, когда условие `n > 1` стало ложным. `do-while` выполнил
тело один раз, хотя условие `attempts < limit` ложно с самого начала. For-each
одинаково записывается для `List` (через итератор) и для массива (через
индекс).

#### break и continue с метками
`break` прерывает ближайший охватывающий цикл, `continue` переходит к его
следующей итерации. Чтобы прервать не самый внутренний, а внешний цикл,
используют метку: `outer:` перед циклом и `break outer;` внутри. Без метки
пришлось бы заводить переменные-флаги для выхода через несколько уровней.

```java
outer:
for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 3; j++) {
        if (i == 1 && j == 1) {
            System.out.println("break outer at i=" + i + " j=" + j);
            break outer;
        }
        System.out.println("i=" + i + " j=" + j);
    }
}
```
```
i=0 j=0
i=0 j=1
i=0 j=2
i=1 j=0
break outer at i=1 j=1
```
После `i=1 j=1` завершился внешний цикл целиком, без булевого флага.

## Частые вопросы на собеседовании

**Q: Чем switch expression отличается от классического switch, а не просто удобнее?**
A: Классический `switch` — инструкция без значения, с проваливанием между
ветками без `break`. Switch expression возвращает значение, его ветки со
стрелками не проваливаются, а для `enum` и sealed-типов компилятор проверяет
исчерпываемость. Стрелочный синтаксис при этом можно использовать и в обычном
switch-операторе, а с Java 21 оба вида умеют `case null` и pattern matching.

**Q: Чему равно i после i = i++ и почему?**
A: Нулю, если `i` было 0. Постфиксный инкремент возвращает старое значение,
затем увеличивает переменную, а потом присваивание записывает в неё
сохранённое старое значение. Инкремент теряется, и компилятор об этом не
предупреждает.

**Q: В чём разница между >> и >>> на отрицательном числе?**
A: `>>` — арифметический сдвиг: копирует знаковый бит, и результат остаётся
отрицательным. `>>>` — логический: заполняет старшие биты нулями, поэтому
отрицательное число становится большим положительным. Для положительных чисел
результаты совпадают.

**Q: Почему `Integer x = flag ? map.get(k) : 0` может упасть с NullPointerException?**
A: Одна ветка — `Integer`, другая — `int`, поэтому тип всего выражения — `int`,
и `map.get(k)` распаковывается. Если ключа нет, распаковка `null` бросает
`NullPointerException`, хотя результат присваивается в `Integer`. Решение —
сделать обе ветки одного ссылочного типа: `Integer.valueOf(0)`.

**Q: Почему for-each работает для List, но не для произвольного класса?**
A: For-each — сахар над `Iterable`: компилятор вызывает `iterator()` и цикл
`hasNext()`/`next()`. Класс, не реализующий `Iterable`, в for-each не
используется, пока не добавить реализацию. Исключение — массивы, для которых
компилятор генерирует цикл по индексу.

## Ловушки и частые ошибки

#### & вместо &&
`if (obj != null & obj.isValid())` компилируется и даёт тот же логический
результат, но правая часть вычисляется всегда. Если `obj` равен `null`, вызов
`isValid()` бросает `NullPointerException`.

#### Проваливание в классическом switch
Без `break` исполнение продолжается в следующей ветке независимо от её
условия. Пропущенный `break` — классическая причина бага, когда код одной ветки
выполняется и для соседней. Switch со стрелками этой проблемы не имеет.

#### Проверка чётности через % 2 == 1
Для отрицательных чисел `x % 2` равно `-1`, поэтому `x % 2 == 1` считает `-3`
чётным. Правильно — `x % 2 != 0` или `(x & 1) == 1`.

#### break без метки во вложенных циклах
Без метки `break` прерывает только самый внутренний цикл. Для выхода сразу из
нескольких уровней нужна метка или вынос циклов в отдельный метод с `return`.
